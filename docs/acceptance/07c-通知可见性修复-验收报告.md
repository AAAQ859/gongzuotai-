- 触发:用户反馈「设置里发送测试通知并没有通知」

## 一、问题诊断(先定位再修)

| 检查项 | 结果 |
|--------|------|
| IPC 链路 | `shell:testNotification` 返回 `{ ok: true }`;`Notification.isSupported()` 为 true |
| Windows 是否收到通知 | 受控实验中点击测试通知前后读取注册表 `HKCU\...\Notifications\Settings\electron.app.Electron\LastNotificationAddedTime`:由 `134370621099356673`(21:15:09)变为 `134370622085233340`(21:16:48)——**Windows 实时接收了 toast** |
| 全局通知开关 | `PushNotifications\ToastEnabled` 未设置(默认开启);无策略禁用 |
| 该应用通知开关 | `electron.app.Electron` 键存在且无 `Enabled=0`(未被单独关闭) |

**结论**:应用已正确把系统通知交给 Windows,但 Windows 没有把它显示为弹窗(banner)。常见原因是「专注助手/勿扰」开启,或该应用通知被设为「仅通知中心」。这类系统侧设置无法由应用代码强制弹出。

## 二、修复内容(保证提醒绝不静默丢失)

| 编号 | 项目 | 说明 |
|------|------|------|
| E1 | 应用内通知兜底 | 新增 `app:in-app-notify` 通道:测试通知与提醒引擎触发时,窗口内同时弹出应用内通知(Element Plus 通知卡,8 秒,可点击跳转对应页面);即使系统弹窗被勿扰抑制,提醒仍然可见 |
| E2 | 提醒引擎双通道 | 引擎 `showNotification` 先发应用内通知(含点击跳转路由),再发系统 toast;系统不支持通知时仅应用内(日志记录) |
| E3 | 设置页诊断提示 | 测试通知成功后提示「已发送系统通知与应用内通知。若没有看到系统弹窗,请检查 Windows 专注助手/勿扰或该应用的通知设置」;卡片底部常驻说明 |
| E4 | 打开系统设置入口 | 新增 `shell:openNotificationSettings`(仅 win32):设置页「打开 Windows 通知设置」按钮直达 `ms-settings:notifications` |
| E5 | 接口类型同步 | preload / index.d.ts 暴露 `onInAppNotify`、`openNotificationSettings`;testNotification 返回增加 `system: boolean` |

## 四、用户复核要点

1. 「设置」→「提醒设置」→ 点「**发送测试通知**」:窗口内会弹「🔔 测试通知」;无论系统弹窗是否被抑制,这条一定能看到
2. 若想看到 Windows 右下角的系统弹窗:点「打开 Windows 通知设置」→ 确认「通知」总开关开启、找到 **Electron**(打包后为「工作台助手」)→ 打开横幅;关闭「专注助手/勿扰」
3. 到点提醒(如会议开始前)触发时:应用内同样会弹「会前提醒」卡片,点击卡片跳到对应页面;系统通知正常时两者都有
4. 打包为 exe(板块 11)后,通知将以「工作台助手」名义显示(安装包会注册开始菜单快捷方式与 AppUserModelID),届时更不易被系统忽略

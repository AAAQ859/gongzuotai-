## 二、实现说明

### 构建与安装包

- 构建工具:`electron-builder 26.15.3` + `electron 44.9.1`,配置见 `work-assistant/electron-builder.yml`
- 应用标识:`appId: com.workassistant.app`,`productName: 工作台助手`,`executableName: WorkAssistant`,版本 `1.0.0`
- 安装包:`oneClick: false`(向导式)、`perMachine: false`(当前用户)、`allowElevation: true`、`allowToChangeInstallationDirectory: true`
- 快捷方式:`createDesktopShortcut` / `createStartMenuShortcut` 均开启,名称「工作台助手」,`runAfterFinish: true`
- 卸载:`deleteAppDataOnUninstall: false`,卸载不删除 `%APPDATA%\work-assistant` 与 `文档\工作台助手`
- 安装界面:简体中文(`installerLanguages: zh_CN`,`language: 2052`,不显示语言选择框)
- 图标:`scripts/make-icon.cjs` 用 Electron `nativeImage` 绘制青绿圆角底 + 白色 W,输出 `build/icon.png`(23 KB)与 `build/icon.ico`(30 KB,含 16–256 多尺寸);安装包、应用、卸载器共用
- 产物名:`工作台助手-Setup-1.0.0.exe`
- 离线/受限网络构建:
  - `electronDist: node_modules/electron/dist`,直接使用已安装 Electron,构建时不再从 GitHub 下载 130 MB 运行时
  - NSIS / winCodeSign 工具提前放入 `%LOCALAPPDATA%\electron-builder\Cache`,并做过 SHA-256 校验

### 运行与数据

- `src/main/index.ts` 在 `app.whenReady()` 前显式把 `userData` 固定为 `%APPDATA%\work-assistant`(产品名改为中文后 Electron 默认目录会变化,固定后可沿用开发版数据)
- Windows 固定 `app.setAppUserModelId('com.workassistant.app')`,与安装包 appId、快捷方式 AUMID 一致
- `app.requestSingleInstanceLock()`:重复启动只激活已有窗口,避免两个进程同时写库、重复提醒;`second-instance` 中恢复最小化窗口并聚焦
- 关闭窗口按设置隐藏到托盘,托盘「退出」走 `before-quit` 标记后真正退出
- 安装版开机自启由 `app.setLoginItemSettings` 注册,路径为安装目录 `WorkAssistant.exe`;托盘、提醒、月末检查在打包环境中正常启动

### 依赖与安全

- 前端依赖(Vue、Vue Router、Element Plus、图标)由 Vite 打包进渲染层,已移到 `devDependencies`,避免 electron-builder 递归打包其运行时依赖树
- 生产依赖仅保留 `adm-zip` 与 `xlsx`;安装包内 `app.asar` 为 9,598,116 字节(84 个条目),不含 `node_modules/vue`、`node_modules/element-plus`
- `xlsx` 从 npm 版 0.18.5 升级为 SheetJS 官方 CDN 的 **0.20.3**(经用户确认):
  - 来源:`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`
  - 本地入库:`work-assistant/vendor/xlsx-0.20.3.tgz`(2,409,319 字节)
  - SHA-256:`8dc73fc3b00203e72d176e85b50938627c7b086e607c682e8d3c22c02bb99fe8`
  - 包内无 `dependencies`、无安装脚本;安装后 `npm ls xlsx` 为 `0.20.3`
  - 修复公告:GHSA-4r6h-8v6p-xvw6(原型污染,< 0.19.3)、GHSA-5pgg-2g8v-p4x9(ReDoS,< 0.20.2)
- 因 `xlsx` 是 `file:` 依赖,electron-builder 的自动依赖收集存在不确定性,已在 `files` 中显式加入 `node_modules/xlsx/**/*`;打包后从 `app.asar` 解出 `node_modules/xlsx/package.json`,确认版本 0.20.3
- **安装包与主程序均未做代码签名**(`Get-AuthenticodeSignature` = `NotSigned`),SmartScreen 会提示未知发布者;这是当前交付的已知限制,安装步骤中给出继续方式

## 四、验收中发现并修复的问题

1. **electron-builder 下载 Electron/工具超时**:首次构建卡在从 GitHub 下载,第二次 `connect ETIMEDOUT 20.205.243.166:443`。处理:配置 `electronDist: node_modules/electron/dist`,并提前把 winCodeSign 2.6.0、NSIS 3.0.4.1、nsis-resources 3.4.1 放入 electron-builder 缓存,构建不再依赖 GitHub。
2. **app.asar 膨胀到约 56 MB**:electron-builder 跟随 vue-router 的运行时依赖收集了 Vite/Babel 等开发工具。处理:前端依赖移到 `devDependencies`(Vite 已将其打入渲染层),生产依赖只保留 adm-zip / xlsx,asar 降至 9.6 MB。
3. **静默安装 `/D=` 路径丢失反斜杠**:Git Bash 参数转换导致安装记录变成 `C:UsersAdministrator...`,文件未复制。处理:对安装路径加单引号并使用 `MSYS2_ARG_CONV_EXCL="*"`,重新安装后路径与快捷方式正确。
4. **`xlsx` 0.18.5 高危公告且 npm 无修复版**:升级到 SheetJS 官方 CDN 0.20.3(用户确认来源),本地 vendor 入库并校验 SHA-256;同时确认安装包内实际版本为 0.20.3,Excel 导出/读取均回归通过。
5. **`file:` 依赖收集存在不确定性**:在 `electron-builder.yml` 的 `files` 显式加入 `node_modules/xlsx/**/*`,打包后解包 asar 核对版本,避免安装版出现「找不到 xlsx」。
6. **截图复验时 `SCREENSHOT_ROUTE` 被 Git Bash 路径转换**:路由变成 `#/C:/Program Files/Git/summary`,截图页不正确。处理:复验命令加 `MSYS2_ENV_CONV_EXCL="*"`,最终截图路由与导航均正确。该问题只影响验收脚本,不影响应用。

## 五、用户复核步骤

1. 双击 `work-assistant\dist\工作台助手-Setup-1.0.0.exe`。
2. 若出现 SmartScreen「Windows 已保护你的电脑」:点「更多信息」→「仍要运行」(安装包未签名,属预期提示;应用完全离线)。
3. 按向导选择安装目录(默认当前用户目录,无需管理员权限),完成安装;确认桌面出现「工作台助手」快捷方式。
4. 双击桌面快捷方式启动:
   - 进入「设置」,确认版本为 1.0.0、托盘状态「运行中」;
   - 点窗口右上角 ×,确认窗口隐藏而托盘图标仍在;单击托盘恢复;
   - 打开「开机自动启动」,在任务管理器启动项中确认;复核完成后请关闭开关。
5. 在「工作纲要」页导出一次 Excel,确认 `文档\工作台助手\工作纲要`(或另选位置)生成 `.xlsx` 且可打开。
6. 进入「数据备份与恢复」点「立即备份」,确认生成 ZIP。
7. 复核数据:安装版应直接显示开发阶段已有数据(数据库 `%APPDATA%\work-assistant\db\work-assistant.db`)。
8. 卸载:Windows「设置 → 应用 → 已安装的应用 → 工作台助手」;确认程序目录与快捷方式删除,而 `%APPDATA%\work-assistant` 与 `文档\工作台助手` 保留。

> 开发模式复核仍可双击仓库根目录 `启动应用.bat`(等价于 `npm run dev`)。

## 一、验收范围

| 编号 | 项目 | 说明 |

| D1 | 字体大小设置(整体缩放) | 设置页新增「显示设置」卡片:小 90% / 标准 100% / 大 110% / 特大 120% 四档;点击立即生效并自动保存(settings 键 ui_zoom),重启应用保持 |
| D2 | 缩放实现机制 | 采用整体缩放(CSS zoom 作用于根元素):字体、按钮、面板按同一比例缩放,浏览器按比例重排,不会出现「只放大文字导致截断/错位」 |

| D5 | 横向滚动兜底 | 页面容器设三栏最小宽度 587px,.app-main 允许横向滚动:极端窄窗口下整体滚动,板块永不互相挤压 |
| D6 | 持久化与回归 | 缩放设置重启保持;全部既有测试回归通过 |

## 二、实现说明(设计决策)

- **为什么用整体缩放**:用户选择「整体缩放(推荐)」。界面按固定像素设计(大量 12/13/14px 字号与固定宽面板),只放大字号会造成文字截断与行高挤压;整体缩放让布局按比例重排,效果与企业微信字体设置一致
- **为什么禁用 Ctrl+滚轮**:页面级缩放会让 CSS 视口变小(相当于窗口变窄),固定宽面板互相挤压——这正是用户描述「板块堆积」的成因之一;统一由设置页缩放,避免两套缩放叠加
- **根元素 zoom 值归一**:设置值经 normalizeUiZoom 防御(空值/非法回退 100%,越界钳制 90%–120%),设置表被手改也不会破坏界面
- **窄窗口修复根因**:通讯录、会议为「侧栏 + 主区 + 300px 详情面板」三栏结构,窄窗时主区被压到 40px,内容竖排堆叠(实测高度 3355px);修复后同样窗口下主区 240px,内容正常卡片排列

## 四、用户复核要点

1. 双击 启动应用.bat →「设置」→「显示设置」:点「大 110%」或「特大 120%」→ 整个界面(字体、按钮、面板)按比例放大,布局不错位;点「小 90%」界面变紧凑
2. 关闭应用重新打开 → 缩放档位保持(设置页对应按钮选中)
3. 按 Ctrl+滚轮或 Ctrl+加号 → 页面不再缩放(避免两套缩放叠加)
4. 把窗口拖到最小(约 1024×700):通讯录/会议/时间轴/日历的侧栏与右侧详情面板自动收窄,主区仍可正常使用,内容不再竖排堆积;若仍过窄,页面出现横向滚动条而不是板块重叠
5. 在 Windows 设置中把「缩放与布局」调为 150% 或从副屏 125% 拖回 100% 屏幕:界面随系统缩放正常重排,板块不重叠
